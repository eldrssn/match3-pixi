# Agent Entry Point

> **match3-pixi** - Match-3 шаблон на Pixi v8 + GSAP 3 + Spine, порт Phaser-шаблона (перенос завершён; история, инварианты и отклонения - [docs/PLAN.md](./docs/PLAN.md)). Рантайм партии - `src/widgets/game`: `lib/bootGameRuntime`, `core/*` (ядро, слои, шина, замок ввода, уничтожение), `motion/*` (GSAP на часах тикера Pixi), `textures/*`, `modules/*` (доска, шапка), `fx/*`, `hud/*`, `spine/*` (ленивый чанк); WebGPU с откатом на WebGL (`?renderer=webgl|webgpu`); бюджет бандла - `npm run bundle:check`. Коротко - раздел «Рантайм Партии» в [CLAUDE.md](./CLAUDE.md), подробно - [docs/game-flow.md](./docs/game-flow.md).

Этот файл - нейтральная точка входа для AI-агентов, которые автоматически читают `AGENTS.md`.

## Project Snapshot

- Проект: Vite + React шаблон игры Match-3 без бэкенда (`match3-pixi`), обычная веб-страница: без моста в нативное приложение, safe-area runtime и десктопной рамки.
- Основной entrypoint: [src/main.tsx](./src/main.tsx).
- Routing: [src/app/routing/Routes.tsx](./src/app/routing/Routes.tsx).
- Экран приложения открывается сразу: общего AppLoader и preload gate нет.
- Session asset warm: [src/shared/lib/assetCache](./src/shared/lib/assetCache) (сессионный blob-стор - у статики нет HTTP-кэша, nginx отдаёт `no-store`; стратегии `blob`/`image`, single-flight с подсчётом ожидающих).
- Level pack editor route `/editor` - только в сборке с флагом `VITE_ENABLE_EDITOR` (константа `__EDITOR_ENABLED__` из `vite.config.ts`: по умолчанию включена в dev и тестах, выключена в `vite build`; без неё ленивый чанк редактора выпадает из бандла и `/editor` уходит в fallback, кнопки «Редактор» на главной нет). [src/pages/editor/EditorPage.tsx](./src/pages/editor/EditorPage.tsx) монтирует [src/widgets/levelConfigEditor](./src/widgets/levelConfigEditor). Страница full-width: колонку `app-frame` не использует; шапка со сводкой и «Применить», колонка настроек - пак (`ui/LevelConfigPackSection`: выбор, новый, id/название, «Экспорт»/«Импорт…» файлом пака, откат черновика), список уровней (`ui/LevelConfigLevelList`: открыть, добавить, дублировать, ↑/↓, удалить; номер = позиция) и настройки уровня (название, ходы, поле, цели, звёзды, бот, JSON). Черновики паков - `model/editorWorkspace` в `localStorage` (`match3-pixi:editor-workspace:v1`), правка уровня пишется в черновик пака через ~300 мс после последней и сразу на `pagehide`/уходе (`model/useEditorWorkspace`; рядом `model/useLevelJson`, `model/useEditorToast`, собирает `useLevelConfigEditor`), id пака применяется по blur/Enter и проходит `isLevelPackId`, секция бота перемонтируется по паку и уровню, история `Ctrl+Z` (`model/useConfigHistory`) - у открытого уровня. Рабочее место - палитра по группам с карточкой элемента, поле и под ним настройки превью (клик, кисть, ПКМ-ластик - `model/useGridBrush`; «Перегенерировать фишки» без потери блокеров). Превью - обычный `GameScreenLazy` с редактором в роли хоста (`ui/LevelConfigPreview`; настройки `ui/LevelConfigPreviewControls` - под полем рабочего места; сессия - `model/usePreviewSession` у `LevelConfigEditor`, общая для настроек и партии, `model/previewOptions`; невалидный уровень - пустое состояние без партии: бустеры, предуровневые бустеры, подсказки, зерно, «+5 ходов» по `resolveContinueOffer` своей плашкой `ui/LevelConfigPreviewContinue`, а не модалкой `outOfMoves` - редактор не зависит от примера хоста); новая партия - новый `key`, монтируется следующей задачей после размонтирования старой (рантайм-синглтоны), бустеры приходят от редактора, а не из каталога внутри виджета. Ширины колонок настроек и превью тянут разделители (`model/editorColumns` + `useEditorColumnWidths`, `localStorage`, показ ужат под окно).
- Паки уровней: [src/entities/level/packs](./src/entities/level/packs) - папка на пак (`pack.json` + `level_<n>_config.json`), находятся `import.meta.glob` в `entities/level/model/levelCatalog` (`LEVEL_PACKS`, `DEFAULT_LEVEL_PACK` = `main`); файл пака из редактора (`ILevelPackFile`, `lib/levelPackFile`) кладётся в репозиторий `npm run levels:import <file>` (проверка, раскладка по файлам, отчёт бота). Название - поле `title` JSON уровня; роли в ритме пака (`rhythm`) в формате нет.
- Main route `/`: однотонный фон и четыре кнопки «Играть · уровень N», «Уровни» (карта уровней, `screen: 'map'`), «Витрина» (уровни по механикам, `screen: 'showcase'`, [src/pages/main/ui/ShowcaseList.tsx](./src/pages/main/ui/ShowcaseList.tsx)) и «Редактор» ([src/pages/main/ui/MainActions.tsx](./src/pages/main/ui/MainActions.tsx)); page [src/pages/main/Main.tsx](./src/pages/main/Main.tsx) - **пример** хоста Match-3 виджета (копия шаблона удаляет его или заменяет своим: виджет и редактор от него не зависят, см. [docs/custom-host.md](./docs/custom-host.md); самый короткий хост - [src/pages/minimalHost/MinimalHost.tsx](./src/pages/minimalHost/MinimalHost.tsx), без маршрута, но под type-check), сценарий партии - [src/pages/main/model/useMainFlowStore.ts](./src/pages/main/model/useMainFlowStore.ts). Чистые правила хоста для переиспользования - [src/features/match3Host](./src/features/match3Host): выбор уровня, бустеры и «+ходы» - `model/partyRules.ts`, прогресс в `localStorage` и знакомые механики - `model/levelProgress.ts` (ключ на пак `levelProgressStorageKey`, у `main` - `match3-pixi:progress:v1`). Главная играет пак `HOST_LEVEL_PACK` (= `DEFAULT_LEVEL_PACK`). Текущий уровень - селектор `selectCurrentLevel` от прогресса (самый дальний открытый), а не поле стора; откуда идущая партия - `party.source` (`{ kind: 'pack', levelNumber }` или `{ kind: 'showcase', key }`; партия витрины прогресс не пишет).
- Match-3 виджет: [src/widgets/game](./src/widgets/game) - `GameScreenLazy` с пропсами `level`/`boosters`/`preBoosters`/`tutorial`/`paused`/`debug`/`insets`/`seed`/`quality` и колбэками `onFinish({ isVictory, score, stars })`/`onOutOfMoves`/`onTutorialSeen`/`onExitRequest`/`onError`/`onBoardEvent(event)` (`IGameScreenProps`; события партии `TBoardEvent` - ход, каскад, спецфишка, шаг и закрытие цели, бустер, очки - выводятся чистыми `listStepBoardEvents`/`diffStoreBoardEvents` из протокола шагов и `GameStore`, а не из спрайтов). Про уровни, модалки и прогресс виджет не знает. Правила доски - чистый движок `BoardEngine` ([src/entities/game/engine](./src/entities/game/engine)): ход разыгрывается синхронно и отдаётся протоколом шагов. Проигрывает их `modules/BoardStepPlayer` (он же начисляет очки по чистому `boardScore` и цели по `listGoalEvents`) по реестру анимаций шагов (`modules/steps`: `DEFAULT_STEP_ANIMATIONS` - запись по всем видам шага, свои анимации копии проекта - только `stepAnimationOverrides.ts` с `(context, step, playDefault)`), выбор цели бустера - `modules/BoosterMode`, буфер ввода под каскадом - `modules/PendingBoardInput`, выбор первого тапа - `modules/SelectionMarker`, `GameLogic` - оркестратор хода (свайп и ход двумя тапами, занятость доски, заряд бустера после `canApplyBooster`, near-miss, финальный бонус, исход). Бот-солвер - [src/entities/game/bot](./src/entities/game/bot), сводка по пакам - `npm run levels:report`.
- App shell: [src/app/App.tsx](./src/app/App.tsx) - каркас на всю видимую высоту окна; высоту пишет только [src/app/hooks/useViewportHeight.ts](./src/app/hooks/useViewportHeight.ts). На десктопе содержимое страниц стоит в колонке `--app-frame-width` (`360 / 700` высоты окна, миксин `app-frame`), фон однотонный во всё окно.
- Modal system: [src/shared/modals](./src/shared/modals) - generic-механика (primitive, host, focus trap на узле диалога, `inert`), [src/widgets/modals](./src/widgets/modals) - реестр/store/views; `shared` не импортирует `widgets`. Store параметризуется ключом (`useShowModal`/`useHideModal`/`useHideModals`/`useIsModalShowed`/`useIsModalMounted`), отдельных `showModalX` нет. В реестре четыре модалки (`levelStart`, `outOfMoves`, `victory`, `defeat`); модалок ошибки и подтверждения выхода нет. Docs: [docs/modals.md](./docs/modals.md), [docs/modals-catalog.md](./docs/modals-catalog.md).
- API-слоя нет: транспорта, авторизации, Axios и TanStack Query нет. Домены без бэкенда: `entities/game`, `entities/level`.
- Build-time env: [vite.config.ts](./vite.config.ts) читает `.env*` и CI-файлы `builds_file.env`/`builds_string.env` через [config/buildEnv.ts](./config/buildEnv.ts). - Current state stack: Zustand + React local state. Redux/RTK Query/OpenAPI generation/TanStack Query сейчас нет.
- Внешних SDK и телеметрии нет: ни аналитики, ни рекламы, ни рантайм-диагностики.

## Rules For Agents

- Не переносить контракты из других проектов без проверки по текущему коду.
- Документация должна описывать только активный runtime этого репозитория.
- Для route/shell изменений сначала проверяй `src/app/routing/Routes.tsx`, `src/shared/constants/model/routes.ts`, `src/pages` и `src/app/App.tsx`.
- `/editor` держи full-width route: не заворачивай его в `app-frame`, иначе правая игра сожмётся в колонку. Ссылки на редактор и его маршрут - только под `__EDITOR_ENABLED__`.
- Пример хоста (`pages/main`, `widgets/modals`) не импортируется из `widgets/game`, `widgets/levelConfigEditor`, `features`, `entities`, `shared`: общее правило хоста кладётся в `features/match3Host`.
- Границы слоёв (`app → pages → widgets → features → entities → shared`, импорт только вниз, в чужой слой - только алиасом `@/`) держит ESLint: `no-restricted-imports`, блок `layerBoundaries` в `eslint.config.js` (плюс `@/widgets/modals` только из `app`/`pages/main`, в `entities/game` - ни скина, ни `?url`, ни `@/shared/lib/assets`, ни относительного пути в соседний срез `entities`). Баррель `@/widgets/game` без Pixi, GSAP и Spine сторожит тест `widgets/game/barrelPixiFree.test.ts` (там же: экран партии статически не тянет Spine); размеры чанков и ленивость движка в сборке - `npm run bundle:check`. Нарушение чини переносом кода вниз, а не `eslint-disable`.
- Видимые строки - только словари слоёв (`widgets/game/texts.ts`, `widgets/modals/texts.ts`, `pages/main/texts.ts`, `widgets/levelConfigEditor/model/texts.ts`, `entities/game/texts.ts`, `entities/level/texts.ts`, `shared/texts.ts`), только русский, без i18n; подписи элементов - в скине. Ключи `localStorage` - только `STORAGE_KEYS` (`shared/constants/model/storageKeys.ts`, префикс `match3-pixi`, переноса старых ключей нет).
- Главная `/` — однотонный фон и четыре кнопки «Играть · уровень N», «Уровни», «Витрина» и «Редактор» (последняя - только при `__EDITOR_ENABLED__`; `src/pages/main/ui/MainActions`); «Играть» открывает карточку уровня `levelStart`, а не партию сразу.
- Для build env/CI изменений сначала проверяй `vite.config.ts`, `config/buildEnv.ts`, `.gitlab-ci.yml`, `Dockerfile` и `README.md`.
- Общего preload нет. Игровые ассеты готовятся при старте партии; локальные состояния загрузки игры и превью редактора сохраняются.
- Авторизации, транспорта и TanStack Query нет; моста в нативное приложение тоже.
- Для layout изменений сначала проверяй `src/app/App.tsx`, `src/app/hooks/useViewportHeight.ts`, `design-scale-root`/`app-frame` в `src/shared/styles/_mixins.scss` и `docs/responsive-layout.md`. Отступы под вырез - только контракт виджета (`insets` / `--match3-inset-*`, `widgets/game/lib/sceneLayout.ts`), глобальных safe-area переменных нет.
- Для modal изменений сначала проверяй `src/shared/modals`, `src/widgets/modals/model`, `src/widgets/modals/ui` и `docs/modals.md`.
- Темп доски по умолчанию - `src/widgets/game/configs/timing.ts` (`DEFAULT_BOARD_TIMING`, плюс соседний `GOAL_INTRO_TIMING` для вступления партии), рантайм читает `BOARD_TIMING` - его же с частичным переопределением скина (`skins/<name>/timing.ts`, `lib/mergeBoardTiming`); в копии проекта темп меняют в скине, не россыпью констант по модулям; всё, что из этих чисел считается (длительность падения от расстояния, stagger колонки, убывающая пауза каскада, волна сборки фона доски `resolveBoardIntroDelayMs`), - чистые правила с тестами в `src/widgets/game/lib/boardTempo.ts`. `CAMERA_PUNCH` остаётся в `lib/boardFxRules`: она держит длительность в паре с интенсивностью. Ввод клетки - `modules/cells/CellInputController` (не `BoardEntity` и не вид клетки), движение клетки (переезд, возврат, дрожь отказа, падение, добор) - `modules/cells/CellMover`; снятие клетки (`destroy`/`vanish`) сразу обрывает её жест (`cancelGesture()`), до анимации. Ход заявляет только `onGlobalPointerUp` - единственная точка коммита; `pointermove` лишь ведёт фишку за пальцем, поэтому увести её за порог и вернуть палец обратно - не ход. Отпускание слушается двумя событиями - `pointerup` и `pointerupoutside` (палец вне canvas / сверху DOM-оверлей): без второй подписки `isDragging` залипает и клетка навсегда перестаёт принимать ходы. Отпускание вне доски - `returnHome` без `commitSwap`. Коммит на пороге уже пробовали и откатили сознательно (доска уезжала под ещё не поднятым пальцем) - обратно не возвращать без отдельного решения. Порог - по доминирующей оси и остаётся на половине клетки, а пара обменивается целиком под пальцем (`GAME_CONFIG.dragFollowTiles`: клетка со свапающимся соседом, четверть с блокером/краем). Пара не прыгает ни в одном исходе: коммит **забывает** смещение не двигая спрайты и доигрывает остаток пути (`moveToCoords` + `scaleToDistance`), а отказ зовёт `returnHome()` - его обязаны звать и пути, где ход отклонён до анимации (занятая доска, край, блокер). Второй половиной пары двигает `modules/SwapDragController` (грид спрайтов `BoardStepPlayer` ему отдаёт колбэком `GameLogic`), геометрия - чистое правило `lib/swapDragOffset` с тестами; владелец обязан звать `releasePartner(true)` там, где ход отклонён после handoff (буферизация под каскадом). Слежение выключено на занятой доске. С выбранным бустером жест хода заперт тоже двумя рубежами: `isBoosterMode` в `CellInputController` выходит из `onPointerDown` до `beginDrag`/нажатия (иначе фишка осталась бы раздутой - сброс живёт в `onGlobalPointerUp`; заодно не считается тап, и тап по спецфишке применяет бустер), а `boosterMode.isActive` в `GameLogic.runSwapRequest` ловит мультитач и возвращает обе половины (`releasePartner(true)` + `returnHome()`), не буферизуя ход. Подсветки выделенной фишки нет - `brightCell()` (`ICellView.bright`) остался только за наведённым бустером. Внешность клетки - вид `ICellView` (`modules/cells/views`: `SpriteCellView` по умолчанию, покадровый `FrameCellView`, скелет `SpineCellView`), выбирает его скин (`board.view`) через реестр `CELL_VIEW_KINDS`, а не `switch`; что рисовать (текстура по прочности, масштаб, украшение, разрушение) - `look()` сущности. Ход списывается при валидации свапа (`spendMove`), а проверка конца партии остаётся в `refreshBoardState` - после каскада.
- Переход «Играть -> доска» - монтирование `GameScreenLazy` вместо контента главной, без анимации смены. `transform` на обёртке экрана партии запрещён: он стал бы containing block для канваса. Пока чанк партии (`GameScreen` + `pixi` + `gsap`) грузится, виден `GameLoadingShell`, затем спиннер `GameScreen` до `isGameLoaded`; оба на одном месте, второго лоадера с другим оформлением нет. `GameScreen` - только разметка доски: рантаймом (`bootGameRuntime`/`destroy`, канвас, отступы, пауза) владеет `widgets/game/model/useGameRuntime`, события - `useGameRuntimeEvents`, очередь подсказок механик - `useMechanicTips`, отладочные кнопки - `ui/GameDebugActions`. Новая партия - новый `key` (`partyId`), два экрана партии одновременно не монтировать: рантайм-синглтоны (`GameStore`, `renderScale`, `sceneInsets`); второй `bootGameRuntime` гасит прошлый рантайм с `console.warn`.
- Звук - синтез WebAudio без аудиофайлов: рецепты и чистые правила (высота матча по шагу каскада, отметки ходов, такт музыки) - `src/widgets/game/audio/soundRecipes.ts` с тестами (скин переопределяет рецепт по событию `TSoundCue` - `resolveSoundRecipe`; словарь событий и формат рецепта - контракт скина `entities/skin`), проигрывание - `audio/SoundEngine` на своём `AudioContext` (создаётся и разблокируется первым жестом, пауза - по шине рантайма, `close` на `destroy`); звуки доски подаёт `BoardStepPlayer`, отказ/музыку/финал - `GameLogic`, цели и ходы движок слушает в `GameStore` сам. Пока контекст заблокирован, звуки пропускаются, а не копятся. Таймер музыки - оконный `setInterval` (не ускоряется вместе с темпом доски) и снимается в `destroy`. Кнопка звука - `modules/SoundToggle` в левом нижнем углу, выбор - `localStorage` (`audio/soundPreference`).
- Вступление партии (`GameLogic.initAnimation`) идёт внахлёст: ждём только удержания цели (`GameGoalsPannel.playIntroHold`), а полёт цели в шапку (`playIntroOutro`) и сборку доски пускаем параллельно **одним `Promise.all`** - «в воздух» нельзя, `runGuarded('initAnimation')` обязан увидеть упавший твин. Сам сценарий интро (оверлей, подписки, флаги прерывания) живёт в `widgets/game/modules/GoalIntro.ts`, а не полями `GameGoalsPannel`: панель отдаёт ему только геометрию колбэками (`IGoalIntroTarget`) и остаётся владельцем глубины своего слоя; `playIntroHold`/`playIntroOutro` у панели - делегаты. Прерываний два (тап-скип, уничтожение модуля целей), и ветка ушедшей сцены (`isSceneGone`) обязана выходить **до** работы с твинами и контейнером; `destroy()` отпускает ожидание фазы (`release`) и снимает затемнение. Фон доски собирается волной от центра, а не по клетке за кадр; клетки фона рисуются от своего центра (`anchor.set(0.5)` + полклетки к позиции).
- Спецфишки (ракета, пропеллер, бомба, радуга) - фигуры `entities/game/lib/boardShapes` (5 > L/T > 4 > 2×2 > 3). Квадрат 2×2 - полноценная комбинация во всех правилах (`findBoardMatches.squares`, «есть ли ход», подсказка, генератор, перемешка). Свап со спецфишкой - отдельная ветка `BoardEngine.trySwap` без проверки комбинации и без отказа: ход состоялся уже тем, что свайп доведён до спецфишки; две спецфишки дают комбинацию в клетке свапа. Тап любой клетки приходит одним событием `cellTap` (`CellInputController` -> `GameLogic.handleCellTap`, правило - `lib/tapSelection`): выбор фишки для хода двумя тапами, второй тап по соседу - ход, тап по спецфишке без выбора - её взрыв, и он **тратит ход**, как в Royal Match. Задетая взрывом или бустером спецфишка взрывается сама - на месте, до оседания (`strike`/`detonate`, `IChain` - ровно один раз за цепочку). Новая спецфишка заводится в движке (`boardPieces` + `TBoardBlast`), рантайм только проигрывает её шаги (`detonate` в `modules/steps/defaultStepAnimations`, эффекты - `fx/specialFx`).
- Уровни: новая механика заводится в движке (`boardPieces`, `boardSteps`, правило - модулем над `boardState`: `boardDamage`/`boardDetonation`/`boardCascade`/`boardSlime`/`boardMoves`, публичный вход - фасад `BoardEngine`) и формате (`minigameLevelConfig`), рантайм только проигрывает её шаг (функция на вид шага в `modules/steps/defaultStepAnimations`: без неё не скомпилируется). Если механика - цель уровня, её событие добавляется в `listGoalEvents` (`entities/game/lib/boardProgress`): по нему цели считают и партия, и бот - своего учёта в `destroy()` у спрайтов нет. Порядок обращений к `random` и выдачи паспортов в движке - контракт: та же партия с тем же зерном повторяется до клетки. Уровень каталога обязан пройти бот-проверку (`levelCatalog.bot.test.ts`, проект vitest `slow` - `npm run test:slow`, в CI `test:ci` гейтит выкладку: не высыхает, нет тупиков, `greedy` проходит, `casual` не реже порога «сложный» `LEVEL_DIFFICULTY_WIN_RATE` из `entities/level/model/levelDifficulty`; проверяются все паки). Клетку, куда ничто не падает (верх под серединой ряда неподвижных шире двух), движок добирает на месте (`planBoardGravity`, `inPlace` в шаге `settle`) - пустых клеток после хода не бывает, тест каталога это сторожит. Подпись, иконка, текстуры, цвет частиц, звук удара, карточка редактора и подсказка механики нового элемента - одна запись в скине (`src/entities/skin/skins/<name>/elements.ts`), вид на доске - строка в `widgets/game/modules/cells/boardViews.ts` (`BOARD_VIEWS`); чек-лист - [docs/extending.md](./docs/extending.md#как-добавить-механику).
- Перф-гейт: качество отрисовки - модульное `widgets/game/configs/renderQuality.ts` (стартовое выставляет `setRuntimeLevelConfig` из `partyOptions.quality` до замера канваса, понижает `modules/PerfMonitor` по чистому `lib/perfGovernor`; запись всегда через `lib/applyRenderQuality` - модуль и зеркало `GameStore.renderQuality`), канвас под новый DPR пересобирает `useGameRuntime`. Новое украшение, которое стоит fill-rate, обязано выключаться в `low`.
- Хуки тестируй через `@testing-library/react` (`renderHook`, `act`), чистые правила - обычными unit-тестами рядом с файлом.
- Для локального loading UI используй `shared/ui/spinner`: inline режим для потоковой разметки, `overlay`/`noBg` как inner-preloader внутри positioned host с заданной высотой.
- Цвета в стилях - только токены из `src/shared/styles/_colors.scss`; повторяющиеся поверхности - миксины из `src/shared/styles/mixins/_surfaces.scss`; каркас страницы - `page-shell` из `src/shared/styles/_mixins.scss`, а не копия колонки в каждом `*.module.scss`. `--app-frame-width` и `--design-px` объявлены только в `design-scale-root` (`src/shared/styles/_mixins.scss`).
- `prefers-reduced-motion` сознательно не поддерживается нигде в проекте: ни `@media (prefers-reduced-motion)` в стилях, ни `useReducedMotion()` в компонентах, вторых веток анимаций не заводим. Исключений нет - `widgets/game` и `pages/editor` живут по тому же правилу (подробности и осознанная плата - в `CLAUDE.md`, раздел Styles, и `docs/game-flow.md`).
- Статичные URL-ассеты лежат в `public/` по подпапкам типа (`images/`, `fonts/`) и не импортируются модульно. Интерактивные SVG-иконки, которые рендерятся как React-компоненты, лежат в `src/assets` и импортируются через `*.svg?react` (SVGR). Ссылки из JS/TSX на `public` - через `src/shared/lib/assets` (`publicAsset`/именованные экспорты, `import.meta.env.BASE_URL`), из CSS - абсолютные `/...` пути. Исключение - скин: игровые текстуры и иконки элементов живут в папке скина (`src/entities/skin/skins/<name>/images|icons`) и подключаются Vite-импортом `?url` (хеш в имени, база `VITE_CDN_BASE_URL` - от сборки). Игровые текстуры - файлы скина (`textures.files`, 168 px, грузит `assetsConfig`, прогревает `warmGameAssets` - оба через `listSkinTextureFiles`) и процедурные Canvas-текстуры скина (`textures.art`, рисование - `skins/<name>/art`, регистрирует `registerProceduralTextures` (`widgets/game/textures/proceduralTextures`)) под общими ключами; файл под ключом холста его переопределяет. Процедурные текстуры регистрируются только там, исходные атласы кадров (`assets-for-new-match3/`) в `.gitignore` - чужой арт без подтверждённых прав. Масштаб пишется дробью «дизайн-px / ширина текстуры», не десятичным множителем: числитель фиксирует размер, знаменатель - `skinTextureWidth(key)` (ширина файла или холста из скина), поэтому картинка, заменившая холст, сохраняет размер. Текстуры элементов на доске - ширины `cellWidth` скина, доска и панель целей берут общий `BASE_SCALE`. `RENDER_DPR_CAP = 3`, разрешение печати текста считается от `worldScale`, а не от DPR; стартовый размер канваса публикует `bootGameRuntime()`, он же сбрасывает его на `destroy`. Подробности - [docs/skin.md](./docs/skin.md) и [docs/game-flow.md](./docs/game-flow.md#откуда-берутся-игровые-текстуры). Фон главной и партии — сплошные цвета `--bg-main` и `--bg-game`; фоновых картинок и звёзд нет.
- Скин и описание элементов: слой `src/entities/skin` (баррель без движка отрисовки и React), активный скин - `model/activeSkin.ts`, папка - `skins/default/` (манифест, `elements.ts`, `textures.ts`, `palette.ts`, `metrics.ts`, `sounds.ts`, `timing.ts`, `art/`, `images/`, `icons/`). Цвета эффектов и холста интерфейса - `SKIN.colors.fx`/`SKIN.colors.hud`, тинты стадий - `board.stageTints`: цветовых литералов в модулях и классах доски нет. Подпись, иконка DOM, текстуры (покой и стадии), цвет частиц, звук удара, карточка редактора и подсказка механики элемента читаются только через реестр (`getElementLabel`/`getElementIcon`/`getMechanicTip`/`getElementTexture`/...), а не таблицами в редакторе, модалках или рантайме. `entities/game` скин не импортирует (ни `?url`, ни `@/shared/lib/assets`); палитра редактора строится из реестра (`editorTools`), вид на доске - реестр `BOARD_VIEWS` вместо `switch` в `EntityFactory`. Тексты холста (`lib/runtimeText`) берут шрифт из `SKIN.fonts.game`, рантайм ждёт его загрузки (`lib/waitGameFonts`). Скин - ленивый чанк: прогрев на главной берёт URL динамическим импортом; не втягивай `@/entities/skin` статически в eager-граф хоста. Подробно - [docs/skin.md](./docs/skin.md).
