# Как расширять шаблон

Каждый проект - копия шаблона. Здесь - куда идти за типовой правкой; детали
лежат в профильных документах.

| Задача                                           | Где                                                         |
| ------------------------------------------------ | ----------------------------------------------------------- |
| заменить арт, цвета, шрифт, звуки, темп доски    | [skin.md](./skin.md)                                        |
| добавить блокер или спецфишку                    | [ниже](#как-добавить-механику), скин - [skin.md](./skin.md) |
| поменять или дополнить анимацию                  | [ниже](#как-поменять-анимацию)                              |
| добавить или поправить уровни, пак, бот-проверку | [levels.md](./levels.md)                                    |
| встроить партию в своё приложение, свой хост     | [custom-host.md](./custom-host.md)                          |
| поменять тексты интерфейса                       | [ниже](#тексты)                                             |
| ключи `localStorage`                             | [ниже](#ключи-localstorage)                                 |

Перед правкой стоит знать границы слоёв: `app → pages → widgets → features →
entities → shared`, импорт только вниз. Их держит ESLint
(`no-restricted-imports` в `eslint.config.js`): `npm run lint` упадёт на
импорте вверх, на относительном пути в чужой слой, на `@/widgets/modals`
(пример хоста) вне `app` и `pages/main` и на скине, `?url` или
`@/shared/lib/assets` в `entities/game`. Что баррель `@/widgets/game`
статически не тянет Pixi, GSAP и Spine, проверяет тест `barrelPixiFree.test.ts`.

## Как добавить механику

Блокер (ящик, камень, слизь…) или спецфишка (ракета, бомба…) - четыре места
плюс тесты. Компилятор ловит пропуск в каждом из них.

1. **Правило движка** (`entities/game`, без движка отрисовки и без скина).
   - Код в формате: `MINIGAME_PIECE_IDS` или `MINIGAME_SPECIAL_IDS`
     (`lib/minigameLevelConfig.ts`), если элемент бывает целью - ещё
     `MINIGAME_GOAL_IDS`; новые ошибки валидации - в `entities/game/texts.ts`.
   - Фишка движка, паспорт и прочность - `engine/boardPieces.ts`.
   - Само правило - модулем над `boardState` (`boardDamage`,
     `boardDetonation`, `boardCascade`, `boardSlime`, `boardMoves`), вход -
     фасад `BoardEngine`. Новая спецфишка - ещё вид `TBoardBlast`; новый вид
     шага - член `TBoardStep`.
   - Цель: событие в `listGoalEvents` (`lib/boardProgress`), для предмета -
     `PIECE_GOAL_IDS` генератора (`lib/minigameLevelGrid`).
   - Механика, которой учат: код в `LEVEL_MECHANICS` (`lib/levelMechanics`).
   - Случайность - только из зерна партии (`shared/lib/random`), никакого
     `Math.random`.
2. **Описание в скине** - запись в `skins/<name>/elements.ts`: подпись,
   иконка, `board` (текстура, стадии, цвет частиц, звук удара), карточка
   редактора (группа, описание; у спецфишки - `origin` и `area`), подсказка
   механики. Подробно - [skin.md](./skin.md#описание-элемента).
3. **Вид на доске** - строка в `widgets/game/modules/cells/boardViews.ts`
   (`BOARD_VIEWS`). Неподвижному блокеру хватит существующего класса (как
   `StoneEntity`); своё разрушение или украшение - свой класс рядом. Новая
   спецфишка проигрывает свой взрыв (`detonate` в
   `modules/steps/defaultStepAnimations.ts`, эффекты - `lib/specialFx`);
   новый вид шага - функция там же.
4. **Текстура** - файл в `images/` и строка в `textures.ts` (или холст в
   `art/boardArt.ts`) и иконка для DOM, если текстура рисуется холстом.
5. **Тесты и бот.**
   - Юнит-тест правила рядом с модулем движка (`entities/game/engine/BoardEngine.test.ts` или тест модуля в `lib/`):
     урон по слоям, гравитация, цель - на маленькой доске с зерном.
   - Тест скина сам проверит текстуру, ширину кадра и запись элемента.
   - Уровень витрины (`entities/level/showcase`, порядок и подписи -
     `model/showcaseCatalog`): `showcaseCatalog.test.ts` проверит, что
     задуманный ход срабатывает.
   - Уровни пака с механикой - через редактор, секция «Проверка ботом»;
     `npm run test:slow` не пускает слишком сложный уровень,
     `npm run levels:report` - сводка. Бот (`entities/game/bot`) играет
     через `BoardEngine`, поэтому новое правило он видит без правок; правьте
     его оценку хода (`bot/levelBot.ts`), только если механика меняет, какой ход хорош.

Палитра и карточка редактора, цели на карточках, подсказка механики, частицы
и звук удара подхватят запись скина сами.

## Как поменять анимацию

Три места, каждое на свой вопрос:

| Что меняем                                               | Где                                                                                                         |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| длительности, паузы, ускорения                           | скин: `skins/<name>/timing.ts` - [skin.md](./skin.md#анимации-доски-и-темп)                                 |
| как клетка выглядит и анимируется (спрайт, кадры, Spine) | скин: `board.view` элемента + `CELL_VIEW_KINDS` - [skin.md](./skin.md#анимации-доски-и-темп)                |
| как доска показывает шаг хода (взрыв, оседание, каскад)  | `widgets/game/modules/steps/stepAnimationOverrides.ts` - [game-flow.md](./game-flow.md#анимации-шагов-хода) |

Своя анимация шага - только в `STEP_ANIMATION_OVERRIDES` (в шаблоне пустой):
переопределение получает `playDefault` и может дополнить анимацию по
умолчанию или заменить её целиком. Замена обязана сделать с зеркалом доски
то же, что анимация по умолчанию, - расхождение ловит `assertInSync` в dev.
Цели, очки и `onBoardEvent` считаются по шагу вне анимации и от
переопределения не зависят.

## Тексты

Тексты интерфейса - только русский, без переключения языков - лежат словарём
у слоя, который их показывает. Копия меняет формулировку в одном файле:

| Словарь                                                     | Что внутри                                                                       |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `widgets/game/texts.ts` (`GAME_TEXTS`)                      | экран партии: хайп-фразы каскада, отказ рантайма, «Цель», «Очки», «Уровень N»    |
| `widgets/modals/texts.ts` (`MODAL_TEXTS`)                   | карточки примера хоста: уровень, near-miss, победа, поражение, кнопки результата |
| `pages/main/texts.ts` (`MAIN_TEXTS`)                        | главная примера хоста: кнопки, карта уровней, витрина                            |
| `widgets/levelConfigEditor/model/texts.ts` (`EDITOR_TEXTS`) | весь интерфейс редактора, его тосты и описание бот-проверки                      |
| `entities/game/texts.ts` (`LEVEL_VALIDATION_TEXTS`)         | ошибки валидации уровня                                                          |
| `entities/level/texts.ts` (`LEVEL_TEXTS`)                   | ошибки файла пака                                                                |
| `shared/texts.ts` (`SHARED_TEXTS`)                          | подписи примитивов по умолчанию, словоформы «ход»                                |

Подписи элементов, описания для редактора и подсказки механик - не словарь, а
запись элемента в скине (`entities/skin`, `getElementLabel`/`getMechanicTip`).
Названия уровней - данные уровня (`title`), подписи витрины - её каталог.
Пример минимального хоста (`pages/minimalHost`) держит свои три строки прямо
в файле: он и есть пример. Сообщения в консоль - для разработчика и в словари
не входят.

## Ключи localStorage

Все ключи - в `shared/constants/model/storageKeys.ts` под общим префиксом
`STORAGE_PREFIX` (`match3-pixi`):

| Ключ                               | Что хранит                                         |
| ---------------------------------- | -------------------------------------------------- |
| `match3-pixi:progress:v1`          | прогресс пака по умолчанию (`features/match3Host`) |
| `match3-pixi:progress:<packId>:v1` | прогресс остальных паков                           |
| `match3-pixi:sound-muted`          | выключенный звук                                   |
| `match3-pixi:editor-workspace:v1`  | черновики паков редактора                          |
| `match3-pixi:editor-columns:v1`    | ширины колонок редактора                           |

Проект новый, поэтому переноса старых ключей нет. Префикс и версию в ключе у
выпущенной игры не меняют: смена обнуляет прогресс игроков.
